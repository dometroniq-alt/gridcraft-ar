First release of **GridCraft AR** — an Arabic interface and Arabic spreadsheet tools built into [GridCraft](https://github.com/storytold/gridcraft) 0.7.0.

## Downloads
- **`GridCraft-AR-0.7.0-windows-x64.msi`** — Windows installer (64-bit). Self-contained: no internet, no Visual C++ redistributable. Installs beside GridCraft, not over it.
- **`GridCraft-AR-0.7.0-windows-x64-portable.zip`** — the same program without an installer: unzip and run `gridcraft.exe`.

The build is not code-signed; SmartScreen warns once on first run.

## What's in ar.1
- **Arabic interface** (*File › Options › Language*, or follows the system): 990+ strings translated, the whole interface right-to-left — tabs, ribbon groups, buttons, formula bar, sheet tabs and status bar — with Noto Sans Arabic embedded so Arabic reads well on any machine.
- **Arabic workbooks by default**: new sheets run right-to-left and Arabic cells align to the right; saved to `.xlsx` the way Excel reads it.
- **Kashida in cells** — *Home › Kashida* Low / Medium / High stretch Arabic words to fill the cell, the same levels WordCraft AR uses, kept in the file.
- **Visual help on every button and every menu item** (232 entries): a drawn thumbnail that plays as a little film, a plain-words explanation ending in an example, in English and Arabic; menu items show their picture beside their name; buttons answer the pointer with motion.
- **Built-in developer systems** under *View › GridCraft AR*: UI Kit gallery, icon sheet, a self-test that runs every ribbon button on a scratch Arabic workbook, a checklist.

**Credits:** everything that makes this a spreadsheet is GridCraft, by the ArtCraft team and the GridCraft contributors (MIT OR Apache-2.0). Thank you.

## Known issues
- `cargo test -p gridcraft-engine --test command_sequence_fuzz` (seed 0) reports an upstream calc inconsistency unrelated to this fork: after `range.fill` of a spilling array formula over a range, the cell holds a `#SPILL!` error in memory but `0` after a full recalc (`crates/calc`, untouched here). The fork's extra commands only changed the random sequence that reaches it.
